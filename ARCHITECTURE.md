# Architecture

> Generated by /gsd:map-codebase on 2026-11-20

## Overview

**Atelier Clothing Agency** is a luxury e-commerce web application for sneakers and streetwear. It is a **hybrid monorepo** — a Vite-served vanilla JS/HTML frontend backed by a FastAPI (Python) REST API, with Cloud Firestore as the primary database and an in-memory fallback for development.

The frontend runs entirely as a single-page experience driven by `public/runway.js` (97 KB). The backend is a separate FastAPI process on port 8001. All communication is via `fetch()` calls hardcoded to `http://127.0.0.1:8001` — this must be updated to the Render URL for production.

## Components

### Frontend — Clothing Rack (Runway)
- **Purpose:** 3D parabolic clothing rack with size/color selection, add-to-bag
- **Location:** `public/runway.js` (lines 1–600), `public/runway.css`
- **Key exported object:** `AtelierCart` (window-global)
- **Dependents:** `index.html` via `<script src="/public/runway.js">`

### Frontend — Sneaker Orbit
- **Purpose:** 3D Nike sneaker orbit carousel
- **Location:** `public/runway.js` (orbit section), `public/rail.css`
- **Dependents:** `index.html`

### Frontend — Shopping Bag / Cart Dialog
- **Purpose:** `<dialog id="bag-dialog">` — itemized cart, payment switcher, UPI QR, UTR submission, order success, on-demand bill
- **Location:** `public/runway.js` → `renderBagDialog()`, `initBagUI()`, `displayOrderSuccess()`, `generateBillOnDemand()`
- **State:** `bagEntries[]` in memory, persisted to `localStorage["runway-styling-bag-v3"]`
- **Badge update:** `updateCounters()` → targets `[data-cart-count]` + `#popover-cart-badge`

### Frontend — Member Auth Popover
- **Purpose:** Shows logged-in user name/avatar, bag count, sign-out
- **Location:** `index.html` lines 48–67, `public/runway.js` → `syncUserHeader()`
- **State:** `localStorage["atelier_user"]`

### Frontend — Login Page
- **Purpose:** Sign In / Register tabs, Google SSO (simulated), Guest mode
- **Location:** `login.html` (30 KB)

### Backend — API Server
- **Purpose:** FastAPI REST API, CORS-open (`*`), Pydantic v2 validation
- **Location:** `backend/main.py`
- **Start:** `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
- **Dependencies:** `database/` (sibling import — must run from repo root)

### Backend — Orders + Invoice
- **Purpose:** Create orders, retrieve orders, generate JSON invoice and HTML Tax Bill (GST 18% inclusive, CGST 9% + SGST 9%)
- **Location:** `backend/routes/orders.py`
- **Company:** ATELIER COUTURE & STREETWEAR LTD., GSTIN: 07AABCA1234F1Z5

### Backend — UPI Gateway
- **Purpose:** Create UPI payment intent (QR URI), validate UTR (12-digit)
- **Location:** `backend/routes/upi.py`
- **Spec:** YouPI-PG from `E:\UPI GATEWAY` (read-only, never modified)
- **UPI URI format:** `upi://pay?pa=atelier@upi&pn=Atelier Collection&am={INR}&cu=INR&tn={note}`
- **FX rate:** 1 USD = ₹86.50

### Database Layer
- **Purpose:** Firebase Admin SDK singleton, 4-tier credential auth chain
- **Location:** `database/connection.py`
- **Fallback:** In-memory dict (development mode — no credentials needed)
- **Seed data:** `database/seed_data.py` → `database/seed.py`

## Data Flow

### Add-to-Cart Flow
```
User clicks "Add to Bag"
  → AtelierCart.add(item) [runway.js]
  → bagEntries[] updated in memory
  → saveBag() → localStorage
  → updateCounters() → [data-cart-count] badge + #popover-cart-badge
  → renderBagDialog() → <dialog> updated
  → Async: POST /api/cart/guest_session/items [fire-and-forget]
  → bag-dialog auto-opens showing cart contents
```

### UPI Checkout Flow
```
User clicks "Pay via UPI"
  → POST /api/upi/create-intent {orderId, amountUsd, customerName, ...}
  → Backend generates UPI URI + QR data
  → Frontend renders QR code in #upi-qr-container
  → User pays in UPI app, gets 12-digit UTR
  → User enters UTR → POST /api/upi/submit-utr
  → Backend validates UTR (regex ^\d{12}$)
  → POST /api/orders → order saved
  → displayOrderSuccess() shown
```

### On-Demand Bill Flow
```
Order success shown
  → "Do you require an Official Tax Bill?" prompt
  → User clicks "Generate Bill & Tax Invoice"
  → generateBillOnDemand() → GET /api/orders/{id}/invoice
  → Bill rendered in #generated-bill-card
  → "View" → GET /api/orders/{id}/invoice/html (new tab)
  → "Download" → fetch HTML, download as Tax-Invoice-ORD-XXXX.html
```

## Conventions

- **Naming:** camelCase for JS variables, snake_case for Python. API payloads use camelCase (`orderId`, `amountUsd`).
- **Source of truth:** `public/runway.js` → manually synced to `frontend/scripts/runway.js`. Same for `index.html` → `frontend/index.html`.
- **CSS architecture:** 4 CSS files. `store.css` owns header + cart badge. `runway.css` owns rack + 3D. `rail.css` owns horizontal rail. No CSS framework — all hand-written.
- **State management:** No external state library. `localStorage` for persistence. Module-scoped variables for in-memory state.
- **Error handling:** Backend uses Pydantic validation + FastAPI HTTPException. Frontend uses try/catch with `catch(() => {})` fire-and-forget on non-critical syncs.
- **Testing:** No test files found. Zero test coverage.
- **Auth:** Simulated on frontend (localStorage). No real JWT/session on backend routes — `/api/me` reads bearer token but does not enforce it on cart/order routes.

## Technical Debt

- [ ] **Hardcoded localhost** — `public/runway.js` lines 485, 694, 751, 804, 895, 1026, 1036, 1049: all fetch calls use `http://127.0.0.1:8001`. Must switch to `VITE_API_URL` env var or a config constant before production.
- [ ] **No test suite** — 0 unit or integration tests for backend routes or frontend JS.
- [ ] **Frontend auth is simulated** — login.html writes to localStorage but backend routes have no auth enforcement. Any user can access any order ID.
- [ ] **Duplicate source files** — `public/runway.js` and `frontend/scripts/runway.js` are manually synced copies (not symlinked). Same for `index.html` / `login.html`. Drift risk is high.
- [ ] **Large uncompressed assets** — Hoodie PNGs are 600 KB–1 MB each. No WebP conversion, no lazy loading, no CDN.
- [ ] **`seed.py` uses `print()`** — should use `logger` for consistency.
- [ ] **CORS is fully open** (`allow_origins=["*"]`) — should lock down to production domain once deployed.
- [ ] **No rate limiting** on UPI/order endpoints — vulnerable to replay/spam.
- [ ] **Tax Invoice uses placeholder GSTIN** (`07AABCA1234F1Z5`) — replace with real GSTIN before go-live.
- [ ] **`src/` directory is a Vite React scaffold stub** — `src/App.tsx` is 3 lines, `src/main.tsx` is 5 lines. Not used by the actual site. Either integrate or remove.
